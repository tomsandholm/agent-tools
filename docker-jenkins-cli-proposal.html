01 The problem

Host-installed Jenkins is a snowflake

A traditional Jenkins host mixes OS packages, plugin drift, and ad-hoc backups. Upgrades become events. This proposal treats Jenkins as disposable compute plus durable state.

TodayWith Docker Jenkins
Upgrade means touching a long-lived hostRebuild the image; restart the container
Plugin set lives only on that machineDeclared in plugins.txt; updated via CLI
Jobs and config tied to the OS installPersisted on NFS or a named Docker volume
Backups are optional and informalmake jenkins-bulk-backup copies the whole home
Lifecycle is tribal knowledgeMakefile is the runbook
02 The proposal

Three parts. One operating model.

Disposable

Docker controller

custom-jenkins-docker from jenkins/jenkins:lts-jdk21, with Docker CLI and a pinned plugin list baked in. Rebuild to upgrade the platform.

Durable

Volumes

/var/jenkins_home is never in the image. Production binds /srv/nfs_share. Plugin-upgrade mode uses the named volume jenkins-vol.

CLI

Makefile

One file in docker/images/ orchestrates image builds, start and stop, plugin updates, shell access, and full backups.

Multi-arch builder agents (builder-amd64, arm64v8, and others) are the same catalog — not a second ops story.

04 Persistence

Two volume modes, one Jenkins home

Production start

make jenkins-start bind-mounts the NFS share at /srv/nfs_share onto /var/jenkins_home. Jobs and configuration live off-box, so the controller can move or be rebuilt without losing the instance.

Optional helper: make-nfs-docker-volume creates a Docker NFS volume pointed at the same share.

Forced plugin upgrade

make jenkins-start-plugin-upgrade uses the named volume jenkins-vol and sets PLUGINS_FORCE_UPGRADE=true. Same lifecycle targets, different persistence backend for upgrade windows.

Image vs homeNew images omit unsupported Blue Ocean plugins. Existing homes still need Script Console cleanup, then a restart.

06 Day-2 operations

Upgrades, plugins, and full backups are first-class

Plugin management

The image installs from plugins.txt at build time. On a running controller, jenkins-get-cli fetches jenkins-cli.jar, jenkins-list-plugins audits the set, and jenkins-update-plugins installs pending updates then safe-restart.

Unsupported Blue Ocean plugins are removed with script-console-delete-blueocean-groovy in Manage Jenkins → Script Console.

Full backup

make jenkins-bulk-backup
# mkdir /tmp/jenkins-full-backup/<timestamp>
# docker cp jenkins-controller:/var/jenkins_home \
#   /tmp/jenkins-full-backup/<timestamp>

Timestamped directory. Whole home: jobs, plugins, secrets, history. Pair this with image rebuilds so you can roll forward or back.

07 The ask

Adopt the Makefile as how we run Jenkins

This is not a new Jenkins product. It is a turn-key command-line management mechanism: Docker for the runtime, volumes for the instance, Make for every lifecycle action.
